DHCP: How Devices Get an IP

You join a Wi-Fi network, open a browser, and somehow your device already knows where it belongs. Who gave it that information?

You didn't manually type an IP address. You didn't choose a subnet. You didn't enter a gateway.

Yet, a few seconds later, the laptop is online.

Someone had to give it the information needed to join the network.

Meet DHCP

DHCP stands for Dynamic Host Configuration Protocol.

Its job is to automatically provide network configuration information to devices that join a network.

The four-step conversation

When a device needs an address, DHCP usually follows a four-step exchange commonly remembered as DORA.

DISCOVER
→
OFFER
→
REQUEST
→
ACK

1. Discover

The device announces that it needs network configuration. It does not yet have a usable IP address of its own.

2. Offer

A DHCP server responds with an offer. The offer can include an available IP address and other network settings.

3. Request

The device indicates that it wants to use the offered configuration.

4. Acknowledgement

The DHCP server confirms the assignment. The device can now configure its network interface with the information received.

It is not forever

DHCP addresses are commonly given as leases.

A lease means the device is allowed to use the assigned configuration for a particular period of time.

Before the lease expires, the device can communicate with the DHCP server to renew it.

This makes address management much easier when devices regularly join, leave, or move around a network.

What if there are many devices?

Imagine a college network with hundreds of laptops and phones.

If someone had to manually assign every IP address, keep track of them, and make sure two devices never received the same address, managing the network would become painful very quickly.

DHCP automates much of that work.

The result is a network where devices can receive configuration without an administrator manually assigning every address.

Why does DHCP matter in security?

DHCP is not just a convenience mechanism. It also creates useful information about how devices enter a network.

Network defenders may examine DHCP-related logs to understand which device received an address and when.

A network address can change. A device can reconnect later and receive a different address. That is why investigations often need more than just an IP address to identify what happened.

This connects directly to the clues we've already seen: IP addresses, MAC addresses, and now DHCP assignments can all help explain what was happening on a network at a particular time.
