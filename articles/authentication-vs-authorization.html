Authentication vs Authorization

You proved who you are. But that doesn't automatically mean you're allowed to do everything.

A LOGIN REQUEST
Secure Portal
username: kamali
password: •••••••••
SIGN IN

You entered the correct password. What happens next?

The system has to answer two different questions.

WHO? Are you really Kamali?
→
WHAT? What are you allowed to access?

These two questions are closely related, but they are not the same.

Authentication

Authentication is the process of verifying who someone or something claims to be.

AUTHENTICATION ASKS

“Who are you?”

The system checks evidence that supports your identity.

COMMON METHODS

Proof of identity

Passwords, PINs, fingerprints, security keys, and multi-factor authentication can all be used.

AUTHENTICATION FLOW
USER Claims an identity
→
PROOF Password / MFA / key
→
IDENTITY Verified

For example, when you sign in to an account with a password, the service checks whether the credentials match the account.

If the verification succeeds, you have been authenticated.

But being authenticated isn't the end.

Imagine you've successfully signed into a university system.

Your identity is verified.

But should you automatically be able to:

→ View another student's grades?
→ Delete a course?
→ Change administrator settings?
→ Download confidential records?

Probably not.

Authorization

Authorization determines what an authenticated user is allowed to access or do.

AUTHORIZATION ASKS

“What can you do?”

The system checks the permissions associated with your identity.

EXAMPLES

Permissions

Read, write, delete, create, modify, administer, or access specific resources.

ONE LOGIN · DIFFERENT PERMISSIONS
Student View own profile
Teacher View and update course records
Administrator Manage users and system settings

All three users can be authenticated successfully. Their permissions can still be very different.

The easiest way to remember it

AUTHENTICATION Who are you?
→
AUTHORIZATION What can you do?

Here's where cybersecurity gets interesting.

Imagine an attacker obtains a legitimate user's password.

A POSSIBLE ATTACK PATH
1 · Password stolen Attacker obtains credentials
2 · Login succeeds Authentication may succeed
3 · Permissions checked Authorization determines access
4 · Activity monitored Logs can reveal unusual behavior

This is why security doesn't stop at passwords. Strong authentication helps protect identity, while authorization limits what that identity can do.

A security analyst might therefore ask:

Who logged in?
How was the identity verified?
What resources were accessed?
Was that access expected?

Authentication and authorization become important clues when investigating suspicious activity.

One more important distinction

A system can have strong authentication and still have poor authorization.

For example, a legitimate employee may successfully log in, but a mistake in permissions could give that employee access to information they should never have been able to see.

That's why security requires both identity verification and appropriate permissions.

THE SECURITY CHAIN
IDENTITY Who?
→
AUTHENTICATION Prove it
→
AUTHORIZATION Allow only what's permitted
TAKEAWAY

Authentication proves identity. Authorization controls access.

Think of authentication as answering “Who are you?” and authorization as answering “What are you allowed to do?”

In cybersecurity, both matter because a verified identity should not automatically have unlimited access.
