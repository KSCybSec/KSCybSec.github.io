Authentication vs Authorization

You proved who you are. But that doesn't automatically mean you're allowed to do everything.

A LOGIN REQUEST
USERNAME
kamali
PASSWORD
••••••••••
VERIFY IDENTITY

What is the system trying to find out?

TWO DIFFERENT QUESTIONS
WHO? Are you really Kamali?
→
WHAT? What are you allowed to access?

First clue: Authentication

Authentication is the process of verifying someone's identity.

When you enter a username and password, the system is essentially asking:

“Can I verify that you are really this user?”

Authentication can use different types of evidence.

Something you know — password or PIN.
Something you have — security key or authentication device.
Something you are — fingerprint or facial recognition.

Multi-factor authentication combines multiple categories to provide stronger identity verification.

The login succeeded.

AUTHENTICATION RESULT
CREDENTIALS Identity evidence provided
→
AUTHENTICATED The system accepted the identity

But something important still hasn't been answered.

What is this user allowed to do?

Second clue: Authorization

Authorization determines what an authenticated user is allowed to access or perform.

ACCESS DECISION
AUTHENTICATED USER Identity has been verified
→
PERMISSIONS What can this user access?

Consider a college system.

Student: view their own marks.
Teacher: enter or update marks for their classes.
Administrator: manage users and system settings.

All three users may successfully authenticate. Their authorization can still be completely different.

Here's where security gets interesting.

A POSSIBLE ATTACK PATH
PASSWORD STOLEN Attacker obtains credentials
→
LOGIN Authentication may succeed
PERMISSIONS System checks access
→
MONITORING Activity can be investigated

This is why authentication and authorization are separate security controls.

Important: A successful login does not mean the user should automatically have access to everything.

Now think like a security analyst.

You notice an account accessing a sensitive file. Instead of immediately deciding that something is wrong, you start asking questions.

Who logged in?
How was the identity verified?
What did the account access?
Was the account actually authorized to access it?
Was the activity expected?

The important clue is that identity and permission are two different parts of the investigation.

One sentence to remember.

THE DISTINCTION
AUTHENTICATION “Who are you?”
+
AUTHORIZATION “What are you allowed to do?”
TAKEAWAY

Identity comes before permission.

Authentication verifies who a user or system is.

Authorization determines what that authenticated identity is allowed to access or do.

A secure system needs both. Strong authentication does not automatically guarantee correct authorization.
