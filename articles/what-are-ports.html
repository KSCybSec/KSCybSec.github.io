What Are Ports?

You found the building. You found the address. Now there's one more question: where inside the building should your request go?

In the last article, we followed a device across a network and learned about IP addresses.

An IP address helps identify where traffic should go.

But imagine you walk up to a large office building.

You know the building's address.

You walk through the front door...

...and then stop.

Which room are you supposed to visit?

One more clue

If an IP address gets your traffic to the right computer, how does that computer know which service should receive it?

Think about a busy computer

Your computer can do several things at once.

It might be browsing a website while downloading a file, checking email, talking to another computer, and running a game in the background.

Imagine all of those conversations arriving at the same machine.

The computer needs some way to tell them apart.

That's where ports come in.

A port is a numbered communication endpoint that helps network traffic reach the appropriate service on a device.

So if the IP address helps you find the building, the port helps identify the particular doorway or service you're trying to reach.

One computer, many doors

Let's make the idea visible.

SERVER
192.0.2.10
:22 :80 :443 :25

Those numbers represent different ports.

A server could be running several network services at the same time, with each service associated with a particular port.

That means these two destinations are not exactly the same:

192.0.2.10:80 ≠ 192.0.2.10:22

They point to the same IP address, but they identify different communication endpoints.

You've probably already met some

You don't need to memorize hundreds of port numbers.

But a few common ones are useful because you'll see them repeatedly while learning networking and cybersecurity.

Port Common association
22 SSH
25 SMTP
53 DNS
80 HTTP
443 HTTPS

The important part isn't memorizing the table.

It's recognizing the relationship:

IP address → destination
Port → service or communication endpoint

So what happens when you visit a website?

Let's return to our original journey.

You type a website address into your browser.

DNS helps your computer discover the IP address associated with the domain.

Your device then needs to communicate with the appropriate service on that destination.

Website name → IP address → Port → Service

For a typical HTTPS website, that communication commonly uses port 443.

So the request isn't simply saying, “Take me to this computer.”

It's closer to: “Take me to this destination and communicate with the service listening at this endpoint.”

Now ports become interesting for security

Imagine you're investigating a server.

You discover that it has several ports accepting connections.

That immediately gives you useful information.

Maybe port 80 is serving a website. Maybe port 22 is running SSH. Maybe another port belongs to a completely different application.

Each open service becomes something you can investigate.

This is why port scanning is such a fundamental technique in cybersecurity.

A tool such as Nmap can help identify which ports are accessible and, with additional techniques, what services may be running behind them.

But finding an open port doesn't automatically mean you've found a vulnerability.

Think like an analyst

If a server has port 443 open, does that automatically mean the server is vulnerable?

No.

It simply tells you that something is accepting connections there. You still need to understand what service is running, how it is configured, what version it uses, and whether there is anything unusual about it.

Open doesn't mean dangerous

This distinction is worth remembering.

An open port generally means that a service is listening and accepting connections.

A closed port means the destination is reachable, but there isn't a service accepting connections there at that moment.

A filtered port is different again: something, such as a firewall or filtering device, may be preventing you from determining whether the port is actually accessible.

These small distinctions become extremely useful once you start working with network scanners and security logs.

And there's another detail

You might have noticed that we keep saying service.

That's because a port isn't the application itself.

Think of a restaurant.

The door gives customers a way into the building. But behind that door is an actual service: people taking orders, preparing food, and serving customers.

In networking, the port is part of the path used to reach a service.

So when a security professional sees an open port, the next question is often:

“What's actually listening there?”

And that question takes us naturally to the next stage of our journey: identifying services and understanding how they communicate.

Remember this

An IP address helps you find the destination. A port helps identify the service or communication endpoint you want to reach.
