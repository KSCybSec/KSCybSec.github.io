ARP: Finding Devices on a Local Network

You know the IP address. You know the device exists. But how does your computer find the actual network interface that should receive the data?

NETWORKING BEGINNER ~5 MIN READ

Your laptop wants to send something to your phone. It knows the phone's IP address: 192.168.1.20.

There is just one problem. An IP address alone is not enough for local delivery. The laptop needs to know which network interface has that address.

LOCAL NETWORK · LOOKING FOR A DEVICE
LAPTOP 192.168.1.10
ROUTER LOCAL NETWORK
PHONE 192.168.1.20
WHO HAS 192.168.1.20?
ARP REQUEST → “Who has this IP address?”

The missing clue

Earlier, we saw that an IP address identifies a device's network location, while a MAC address identifies a network interface on the local network.

ARP connects those two pieces of information.

ARP stands for Address Resolution Protocol. For IPv4 networks, it is used to discover the MAC address associated with a known IPv4 address on the local network.

So the laptop asks

Imagine the laptop knows that the phone is at 192.168.1.20.

It sends an ARP request onto the local network:

Laptop
→
“Who has 192.168.1.20?”
→
Local Network

Devices on that local network receive the request. The device whose IPv4 address matches the question can answer.

The phone responds with something like:

“192.168.1.20 is me.”
→
MAC: 3C:52:82:7A:91:4F

Now the laptop has the missing clue. It can associate the IP address with the MAC address needed for local delivery.

Request → Reply

That gives us the basic ARP conversation:

ARP · TWO-STEP EXCHANGE
LAPTOP
PHONE
ARP REQUEST
ARP REPLY
Who has 192.168.1.20?
192.168.1.20 → MAC

It doesn't ask every time

Once a computer learns the IP-to-MAC mapping, it can keep that information temporarily in an ARP cache.

That means the laptop does not need to repeat the same ARP request every time it communicates with the phone.

ARP CACHE · EXAMPLE
192.168.1.20
3C:52:82:7A:91:4F
192.168.1.1
84:16:F9:2B:44:08

The exact entries and their lifetime can change as the network changes. The important idea is simple: the cache remembers recently learned mappings.

Why does this matter in security?

ARP is a normal and necessary part of IPv4 local networking. But because local devices trust ARP information, incorrect mappings can cause problems.

One example is ARP spoofing, where forged ARP information can make a device associate an IP address with the wrong MAC address.

You do not need to learn the attack yet. For now, remember the security lesson: when a system relies on a mapping, changing that mapping can change where traffic goes.

This is exactly the kind of relationship security analysts learn to recognize: one small piece of network information can explain what happened to the traffic.

PAUSE FOR A SECOND

If your computer knows an IP address but not the corresponding MAC address, what protocol can help it discover that mapping on an IPv4 local network?

One important boundary

ARP is associated with IPv4.

IPv6 uses a different mechanism called Neighbor Discovery Protocol (NDP).

You do not need to dive into NDP yet. Just keep the distinction in mind as you continue learning networking.

The bigger picture

We have now connected several clues:

IP tells us where a device is logically located. MAC identifies the local network interface. ARP helps connect those two pieces of information for IPv4.

And once a device has an IP address, a MAC address, and a way to communicate locally, another question appears: how did it get that IP address in the first place?

TAKEAWAY · 019

ARP helps an IPv4 device discover the MAC address associated with a known IP address on the local network. It works through ARP requests and replies, and learned mappings can be kept temporarily in an ARP cache.
