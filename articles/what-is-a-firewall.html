What Is a Firewall?

Your computer is constantly communicating with other systems. But should every connection be allowed?

Imagine you're sitting at home working on your laptop.

Your browser is open. You're watching a video in another tab. Maybe you're downloading a file.

All of these things involve network communication.

Data is coming in. Data is going out. Different applications are talking to different services.

Now imagine that your computer suddenly receives a connection request from somewhere you've never heard of.

Should it allow the connection?

Pause here

If your computer accepted every connection automatically, what could possibly go wrong?

That's the problem we're about to solve.

Let's go back to the network

In the previous articles, we followed a request across the Internet.

A domain name was translated into an IP address. A port identified a service. TCP or UDP carried the communication. HTTP or HTTPS handled the web conversation.

Domain → DNS → IP → Port → Service

But there's another question we haven't really asked yet.

“Should this traffic be allowed to continue?”

This is where a firewall enters the picture.

Think of a security checkpoint

Imagine a building with a security checkpoint at the entrance.

People arrive. The security guard checks certain information. Some people are allowed inside. Others aren't.

A firewall works with a similar idea, but for network traffic.

A firewall monitors network traffic and applies rules to decide whether traffic should be allowed or blocked.

That's the core idea.

But how does it decide?

A firewall doesn't simply look at traffic and magically know whether something is “good” or “bad.”

It works using rules.

Those rules can consider information such as the source, destination, protocol, port, and connection state.

Based on its configuration, the firewall can then allow or block the traffic.

Here's where ports become useful again

Remember the idea of ports?

One computer can run many network services at the same time.

A firewall can use those ports when deciding what traffic is permitted.

For example, a system might intentionally allow web traffic through ports 80 and 443 while blocking an unnecessary service on another port.

The exact rules depend on the system and its purpose.

A web server, a personal laptop, and a corporate server may all need different firewall rules.

Now imagine you're a security analyst

You notice that a server is receiving connection attempts on several ports.

Some are expected. Others aren't.

You check the firewall logs.

They show which traffic was allowed and which traffic was blocked.

Suddenly, the firewall isn't just a barrier anymore.

It's also producing information that can help you understand what's happening on the network.

Security isn't only about blocking something.
Sometimes the evidence left behind is just as important.

There isn't just one kind of firewall

Firewalls can exist in different places.

Your operating system can have a firewall. A network can have a firewall between different systems. Organizations can use dedicated firewall devices or cloud-based firewall services.

They may also inspect traffic at different levels and use increasingly sophisticated rules.

You don't need to memorize all the types yet.

For now, keep the main idea in your head:

A firewall is a control point between network traffic and the system or network you're trying to protect.

One important misunderstanding

A firewall is useful.

But it isn't a magic shield.

A firewall can control traffic according to its rules. It cannot automatically solve phishing, stolen passwords, vulnerable applications, malware, or every other security problem.

That's why cybersecurity uses layers.

A firewall might control network access. Authentication protects accounts. Encryption protects information in transit or at rest. Monitoring helps detect suspicious activity. Security teams investigate what those systems report.

Each layer has a different job.

And now the network looks a little different

At the beginning of this path, the Internet probably looked like one huge invisible thing.

Now we can start breaking it apart.

Domain → DNS → IP → Port → TCP / UDP → Firewall → Service

And every one of those pieces gives us another clue about how digital communication works.

Remember this

A firewall controls network traffic using rules, helping decide what should be allowed to reach a system or network and what should be blocked.
