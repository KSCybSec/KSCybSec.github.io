Common Network Protocols

Devices don't just send data randomly. They follow agreed rules that tell them how communication should happen.

NETWORKING BEGINNER ~5 MIN READ

You open a website.

Your device finds the destination, sends traffic through the network, and eventually receives a response.

But there is an important question hiding underneath all of this:

How do two completely different systems agree on what that communication means?

They use protocols.

What is a protocol?

A network protocol is a set of agreed rules that defines how devices communicate.

Think about two people having a conversation. They need a shared language and some understanding of how the conversation works.

Computers need something similar.

A protocol can define things such as how a message is structured, how it is sent, how it is received, and what the receiver should do with it.

Each protocol has a different job. They are not competing with each other. They work at different parts of the communication process.

Protocols you'll meet everywhere

DNS
Helps translate domain names such as example.com into IP addresses.
DHCP
Automatically provides devices with network configuration such as an IP address, subnet mask, gateway, and DNS server.
ARP
Helps IPv4 devices discover the MAC address associated with a local IPv4 address.
TCP
Provides reliable, ordered delivery of data between endpoints.
UDP
Provides a lightweight transport method without TCP's connection and delivery guarantees.
HTTP
Defines how web clients and servers exchange web resources.
HTTPS
HTTP communication protected using TLS.
SSH
Provides secure remote access and other secure communication functions over a network.

Protocols have different jobs

It helps to stop thinking of protocols as one giant list.

Instead, think about where they fit into a conversation.

For example, DNS can help answer “Where is this website?”

TCP can help provide “How should this data be delivered reliably?”

HTTPS helps define “How should this web communication be protected?”

Different questions. Different protocols. One communication process.

Where does security enter?

Protocols are important to cybersecurity because security problems can appear when communication rules are weak, misconfigured, outdated, or used incorrectly.

That's why security professionals spend so much time looking at network traffic.

A network packet is not just “data moving around.” It can contain clues about who is communicating, where the communication is going, which protocol is being used, and what kind of service is involved.

This is one reason tools such as Wireshark are useful in defensive security and network investigations.

If you understand the protocol, unusual traffic becomes much easier to recognize.

The important part isn't memorizing them

You don't need to memorize a huge protocol table before continuing.

The more useful skill is recognizing what a protocol is trying to do.

When you see DNS, think name resolution.

When you see DHCP, think network configuration.

When you see ARP, think local IPv4-to-MAC resolution.

When you see TCP, think reliable transport.

When you see UDP, think lightweight transport without TCP's reliability mechanisms.

When you see HTTP or HTTPS, think web communication.

TAKEAWAY · 024

Network protocols are agreed rules that allow systems to communicate. Different protocols perform different jobs: DNS helps with name resolution, DHCP provides network configuration, ARP resolves local IPv4 addresses to MAC addresses, TCP and UDP handle transport, and HTTP/HTTPS support web communication. Understanding these roles is important when reading and investigating network traffic.
