NETWORKING · 028 · BEGINNER

Reading an
Nmap Scan

Running Nmap is only half the job. The useful part is understanding what the results are actually telling you.

NETWORKING ~5 MIN READ LEARN · THINK · VERIFY

You run your first Nmap scan.

A few seconds later, the screen fills with text.

Ports. States. Services. Numbers.

But what are you actually looking at?

Knowing the command is useful. Knowing how to read the answer is much more important.

Let's take one small Nmap result and follow the clues.

TARGET
192.168.1.20
→
RESULT
PORTS + SERVICES
HOST UP   ·   PORT OPEN   ·   SERVICE HTTPS

A scan takes something you started with — an IP address — and gives you more information to investigate.

Start with the output

Here's a simplified example of what an Nmap result might look like:

NMAP RESULT · SIMPLIFIED
Starting Nmap scan... Nmap scan report for 192.168.1.20 Host is up. PORT STATE SERVICE 22/tcp open ssh 80/tcp open http 443/tcp open https Nmap done.

Don't try to understand everything at once.

Read it from top to bottom.

First clue: the host

You might see:

Nmap scan report for 192.168.1.20 Host is up.

The target is identified by its IP address.

Host is up means Nmap received enough of a response to determine that the target appears reachable.

That's your first clue:

There is a responding device at this address.

Second clue: the port

Now look at:

22/tcp 80/tcp 443/tcp

The number is the port. The part after the slash tells you the transport protocol.

For example:

22/tcp
Port 22 using TCP.
80/tcp
Port 80 using TCP.
443/tcp
Port 443 using TCP.

Remember the earlier article: ports act like numbered communication endpoints.

So now the machine isn't just 192.168.1.20.

We know that certain communication endpoints are responding.

Third clue: the state

This is one of the most important parts of the result.

Nmap can report different port states.

OPEN
An application appears to be accepting connections on the port.
CLOSED
The host responded, but no application is currently accepting connections on that port.
FILTERED
Nmap cannot determine whether the port is open because filtering is preventing a clear response.

These states are clues about what happened during the scan.

They do not automatically tell you whether a system is secure.

Fourth clue: the service

Now look at the last column:

PORT STATE SERVICE 22/tcp open ssh 80/tcp open http 443/tcp open https

Nmap associates these ports with common service names.

Port 22 is commonly associated with SSH. Port 80 with HTTP. Port 443 with HTTPS.

But remember: the port number alone does not prove what service is running.

Services can be configured differently. Nmap can perform additional detection when you need more detail.

Now connect the clues

Let's say this is a web server you're responsible for.

You expected HTTPS.

The scan shows:

443/tcp open https

That makes sense.

Then you notice:

22/tcp open ssh

That might also be expected. Perhaps administrators use SSH to manage the server.

The important question is not:

"Is port 22 bad?"

Instead ask:

"Is this service supposed to be reachable from this network?"

Context changes everything.

An open port is not automatically a vulnerability

This is worth remembering early.

Suppose Nmap reports:

80/tcp open http

That means something appears to be accepting connections there.

It does not automatically mean the service is vulnerable.

You would need more information: what software is running, which version, how it is configured, who can reach it, and whether any known security issues apply.

The scan gives you a direction.

This is how reconnaissance works

Think about the chain we've built.

IP
192.168.1.20
→
PORT
443/tcp
→
SERVICE
HTTPS

This is the beginning of reconnaissance: collecting information about a system before deciding what deserves closer attention.

Defenders use the same information from the other side. They want to know what their systems expose too.

Read the result like a story

Instead of memorizing every line, ask four simple questions:

1. What host am I looking at?

2. Which ports responded?

3. What state is each port in?

4. What service might be behind it?

Once you can answer those four questions, a basic Nmap result becomes much less intimidating.

TAKEAWAY

Reading Nmap is about connecting clues: host → port → state → service.

An Nmap scan doesn't tell you that a system is vulnerable. It tells you what deserves your attention next.
