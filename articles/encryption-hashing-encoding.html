Encryption, Hashing & Encoding

They can all make information look completely different. But they solve very different problems.

THE ORIGINAL MESSAGE
PLAIN DATA
Meet me at 8 PM.

Now something changes.

The message is transformed. Someone looking at the result may no longer understand it immediately.

THREE POSSIBILITIES
METHOD 01

Encryption

Protect information so that authorized parties can recover the original data.

METHOD 02

Hashing

Transform data into a fixed-length value designed to work as a one-way representation.

METHOD 03

Encoding

Represent data in another format so systems can store, transmit, or process it correctly.

Let's follow each clue.

01 · Encryption

Encryption is about protecting information from unauthorized access.

ENCRYPTION
PLAINTEXT Readable information
→
CIPHERTEXT Protected information

A cryptographic key is used as part of the encryption process. With the appropriate key and algorithm, the protected data can be decrypted.

Imagine sending sensitive information across a network.

Without protection: someone who intercepts the data may be able to read it.
With encryption: the intercepted data is intended to remain protected from unauthorized readers.

HTTPS, encrypted messaging, encrypted files, and many other security systems rely on cryptography.

02 · Hashing

Hashing works differently.

A hash function takes input and produces a fixed-length output, often called a hash value or digest.

HASHING
INPUT Any supported data
→
HASH Fixed-length digest

A properly designed cryptographic hash function is intended to make it computationally infeasible to recover the original input directly from the hash.

More importantly, even a tiny change in the input should produce a very different hash value.

SMALL CHANGE · DIFFERENT RESULT
Hello Hash A
hello Hash B

The two inputs differ by only one character, but their hash outputs can be completely different.

Why does hashing matter for passwords?

A well-designed password system should not need to store users' original passwords in readable form.

PASSWORD VERIFICATION
YOUR PASSWORD Entered during login
→
HASH Compared with stored verifier

Modern password storage should use dedicated password-hashing algorithms with salts and appropriate work factors, rather than simply applying a fast general-purpose hash such as SHA-256.

03 · Encoding

Encoding is different again.

Encoding changes how information is represented so that it can be stored, transmitted, or processed by another system.

ENCODING
DATA Original representation
→
ENCODED DATA Another representation

A familiar example is Base64.

TEXT
Hello

BASE64 REPRESENTATION
SGVsbG8=

Base64 may look mysterious at first glance, but it is not encryption. Anyone can decode Base64 if they know the encoding.

Important: Encoding is not a security mechanism by itself.

So how do you tell them apart?

Encryption Protect data → authorized parties can decrypt it
Hashing Produce a one-way digest for verification and other uses
Encoding Change representation → decode using the known format

Here's where this becomes useful to a security analyst.

During an investigation, you might encounter a strange-looking string in a URL, log file, configuration file, or application response.

Don't immediately assume: “That's encrypted.”

First ask:

→ Could this be an encoded value?
→ Could it be a hash?
→ Is there evidence that encryption is being used?
→ What system produced it?
→ What context surrounds the value?

The appearance of a string alone usually isn't enough to identify what produced it.

One final clue

SECURITY PURPOSE
ENCRYPTION

Confidentiality

Helps prevent unauthorized parties from reading protected data.

HASHING

Integrity & verification

Useful for checking data and securely verifying information such as passwords when used appropriately.

ENCODING

Compatibility

Helps systems represent and exchange data in expected formats.

TAKEAWAY

Same appearance. Different purpose.

Encryption protects data and is designed to be reversible with the appropriate key.

Hashing creates a one-way digest that can be used for verification and integrity-related tasks.

Encoding changes representation so information can be handled or transmitted in a compatible format.

When you encounter unfamiliar data during an investigation, don't guess from appearance alone. Look at the context.
