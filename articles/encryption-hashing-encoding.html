Encryption, Hashing & Encoding

They can all make information look completely different. But they solve very different problems.

THE ORIGINAL MESSAGE
PLAIN DATA
Meet me at 8 PM.

Something changed.

The message no longer looks the same. But what actually happened to it?

CONTEXT Find out what actually happened

First clue: Encryption

Encryption is about protecting information from unauthorized access.

ENCRYPTION
PLAINTEXT Readable information
→
CIPHERTEXT Protected information

Encryption uses a cryptographic algorithm and key to transform readable data into protected data.

With the appropriate key and cryptographic process, the protected data can be decrypted back into usable information.

Imagine sending sensitive information across a network.

Without encryption: an unauthorized party who obtains the data may be able to read it.
With encryption: the data is intended to remain unreadable to unauthorized parties.

HTTPS, encrypted messaging, encrypted storage, and many other security systems use cryptography to protect information.

Second clue: Hashing

Hashing has a different purpose.

A hash function takes input and produces a fixed-length output called a hash value or digest.

HASHING
INPUT Original data
→
HASH Fixed-length digest

A cryptographic hash function is designed so that it is computationally infeasible to recover the original input directly from the hash.

A TINY CHANGE
Hello One hash value
→
hello A completely different hash value

Even a small change in the input can produce a dramatically different hash.

Why does hashing matter for passwords?

A secure password system should not need to store users' original passwords in readable form.

PASSWORD VERIFICATION
PASSWORD Entered during login
→
VERIFICATION Compared against stored password verifier

Modern password storage uses dedicated password-hashing algorithms with salts and appropriate work factors. Simply storing passwords or using a fast general-purpose hash is not sufficient password protection.

Third clue: Encoding

Encoding is different from both encryption and hashing.

It changes the representation of information so that systems can store, transmit, or process it using an expected format.

ENCODING
ORIGINAL TEXT
Hello

BASE64
SGVsbG8=

Base64 is a common example.

The result may look complicated, but Base64 is not encryption. Anyone who knows the encoding can decode it.

Important: Encoding is not a security mechanism by itself.

So what is the difference?

FOLLOW THE PURPOSE
ENCRYPTION Protect data
→
DECRYPT Recover the protected data
HASHING Create a digest
→
VERIFY Compare or check information
ENCODING Change representation
→
DECODE Return to the original representation

Now imagine you're investigating a system.

You find a strange-looking string inside a log file, URL, configuration file, or application response.

Don't immediately conclude:

“That's encrypted.”

Instead, investigate.

→ Could it be encoded?
→ Could it be a hash?
→ Is encryption actually being used?
→ Which application produced it?
→ What does the surrounding context tell you?

The appearance of a string alone usually isn't enough to determine how it was produced.

The clue is the purpose.

THINK LIKE AN INVESTIGATOR
ASK WHAT THE SYSTEM IS TRYING TO DO

Protect information?
Think encryption.

Create a digest for verification?
Think hashing.

Represent information in another format?
Think encoding.

TAKEAWAY

They may look similar. Their purposes are not.

Encryption protects information and is designed to be reversible using the appropriate cryptographic process.

Hashing produces a one-way digest useful for verification, integrity-related tasks, and password storage when appropriate algorithms are used.

Encoding changes the representation of data so that systems can store or transmit it in an expected format.

When you encounter unfamiliar data, don't guess from appearance. Look at the context and purpose.
