What Is OSINT?

A beginner-friendly introduction to Open Source Intelligence.

Have you ever searched for your own name on Google?

Maybe you found an old social media profile. Maybe an old photo showed up. Maybe you found something you completely forgot you had posted.

You didn't hack anything.

You just searched for information that was already publicly available.

And that simple idea is where OSINT begins.

🔎 First things first: what does OSINT actually mean?

OSINT stands for Open Source Intelligence.

Don't let the word intelligence make it sound complicated.

At its simplest, OSINT is about:

Finding information from publicly available sources, connecting the pieces, and figuring out what they actually tell you.

Think of yourself as an investigator.

You start with one small piece of information.

Maybe it's:

  • a username
  • an email address
  • a website
  • an image
  • a domain name
  • a company
  • an IP address

Then you ask:

“What else can I find?”

That's when things start getting interesting.

🧩 Let's imagine a small investigation

Fictional training example

The usernames and accounts in this example are fictional and are being used only to demonstrate OSINT concepts.

Suppose you come across this username: 

shadowfox23

That's all you have.

Not much, right?

So you search for it.

You find a GitHub account using shadowfox23.

Interesting.

The GitHub profile contains a link to another website.

That website contains a profile picture.

You search that image and discover that the same image appeared somewhere else years ago.

Now you have several pieces of information.

But here's the important part:

You haven't proved anything yet.

You've only found connections worth investigating.

And that's a very important OSINT mindset.

A clue is not the same thing as proof.

🌐 Where does OSINT information come from?

This is where beginners sometimes get confused.

OSINT isn't one website or one tool.

Information can come from many different places.

🔎 Search engines

Google, Bing and other search engines can help you discover publicly indexed pages.

You can search for things like: 

"shadowfox23"

or: 

"shadowfox23" github

You aren't doing anything magical here.

You're simply asking a search engine:

“Show me where this appears.”

👤 Social media

Public profiles can contain useful clues such as:

  • usernames
  • profile names
  • websites
  • public posts
  • profile images
  • dates
  • publicly shared interests

One profile by itself might tell you very little.

Several public profiles using the same username can become much more interesting.

But again:

Same username ≠ automatically the same person.

🌐 Public websites and records

Depending on the investigation and applicable laws, useful information can also come from:

  • company websites
  • government portals
  • public documents
  • news websites
  • technical documentation
  • domain registration information
  • public repositories

The source matters.

So does how you interpret it.

🕵️ So how does an OSINT investigation actually work?

There isn't one magical button called “Investigate.”

Most investigations are more like this:

01 Question
02 Search
03 Collect
04 Connect
05 Verify
06 Report

1. Ask a question

Good investigations start with a question.

Not:

“Let me search everything about this person.”

Instead:

“Is this username connected to this GitHub account?”

That's much more specific.

A clear question gives your investigation a direction.

2. Search

Now you look for information related to your question.

For our example: 

"shadowfox23"

Then perhaps: 

"shadowfox23" github

Then: 

site:github.com "shadowfox23"

That last search introduces something useful:

Search operators.

We'll cover those properly in another guide.

3. Collect

You find something useful.

Don't immediately jump to a conclusion.

Record it.

Finding Source Why it matters
Username shadowfox23 GitHub Possible identity clue
Same username elsewhere Public profile Possible connection
Same profile image Image search Potential supporting clue

You're building an evidence trail.

This is important because investigations can quickly become confusing when you have several tabs open and can't remember where a particular piece of information came from.

4. Connect

Now comes the fun part.

You ask:

“Do these pieces actually connect?”

Maybe two accounts use the same username.

Maybe both link to the same website.

Maybe the same public profile picture appears on both.

Each connection gives you another clue.

But don't force connections just because they look interesting.

A good investigator should be comfortable saying:

“I don't have enough evidence yet.”

That's better than making a confident guess.

🧠 Quick challenge

Would you call this a match?

Imagine you find this:

GitHub 

Username: shadowfox23
Location: Chennai

And then you find:

Reddit 

Username: shadowfox23
Location: Chennai

Would you say:

“It's definitely the same person.”

❌ Not yet.

It could be the same person.

But it could also be two different people who happen to use the same username and location.

You need more evidence.

Maybe both accounts link to the same website.

Maybe they use the same unique profile image.

Maybe one account references something that also appears on the other.

Maybe there is another independent clue connecting them.

That's how you increase confidence.

🔍 5. Verify

This might be the most important step.

You found information.

Now ask:

“How do I know this is actually correct?”

This is where good OSINT differs from simply being good at Googling.

Let's say you find an article claiming something happened in 2022.

Before using it in your investigation, you might check:

  • Who published it?
  • When was it published?
  • Is another reliable source reporting the same thing?
  • Is the original source available?
  • Could the information be outdated?
  • Is the page actually talking about the same person or organisation?
Finding ≠ proving.

A search result is a starting point.

It isn't automatically the final answer.

🛠️ What tools do OSINT investigators use?

You don't need 50 tools to start.

In fact, learning why you're using a tool is more important than collecting tools.

🔎 Search engines

Useful for discovering publicly indexed information.

Examples:

  • Google
  • Bing

Start here more often than you might think.

🌐 WHOIS and domain information

Domain registration services can provide information about a domain's registration and related details, depending on what is publicly available.

For example, you might investigate: 

example.com

and discover registration-related information.

But privacy protection and modern registration practices mean you won't always see someone's personal details.

That's normal.

The goal isn't to force information out of a service.

The goal is to understand what information is actually available.

🦠 VirusTotal

VirusTotal can be useful when investigating suspicious:

  • files
  • URLs
  • domains
  • IP addresses

It can provide detections, reputation information, relationships and other security intelligence collected from multiple sources.

For a SOC analyst, this can become especially useful when investigating suspicious indicators.

But remember:

A tool result is evidence to investigate, not automatically the final verdict.

🖼️ Reverse image search

You have an image.

Instead of asking:

“What does this image show?”

you can ask:

“Where else has this image appeared?”

That's a completely different question.

It can help you discover:

  • older versions of an image
  • other websites using it
  • possible original sources
  • related images

Imagine you're investigating another fictional username: 

cyberfox_42

You search: 

"cyberfox_42"

You find: 

GitHub
Reddit
A personal website

Now you have three possible leads.

You check GitHub.

You find a link to: 

cyberfox.example

You check the website.

It uses the same username.

Interesting.

Then you find a public profile picture that appears on both.

Now you have several independent clues pointing in the same direction.

Notice what we didn't do:

  • We didn't hack an account.
  • We didn't bypass a login.
  • We didn't steal private information.

We simply investigated information that was publicly available.

That's the basic idea behind OSINT.

⚠️ Here's where beginners can go wrong

OSINT can be surprisingly powerful.

That's exactly why you need to be careful.

Just because information is publicly visible doesn't mean you should use it however you want.

A responsible investigator should think about:

  • privacy
  • legality
  • consent
  • context
  • accuracy
  • potential harm

And never assume that because you can find something, you automatically should use it.

Good practice for learning

Stick to your own accounts, fictional identities, public organisations, test data, and authorised investigations.

🧠 A small OSINT mindset shift

Here's something I want you to remember.

Beginners often ask:

“What tool should I use?”

A better question is:

“What am I trying to find out?”

Question:

Who registered this domain?

→ Investigate available domain-registration information.

Question:

Where else does this username appear?

→ Search for username reuse.

Question:

Where did this image originally appear?

→ Investigate the image and its previous appearances.

Question:

Is this suspicious domain associated with known malicious activity?

→ Investigate security intelligence sources.

The question determines the technique.

Not the other way around.

📌 OSINT in one picture

If you forget everything from this article, remember this: 

              QUESTION
                  ↓
               SEARCH
                  ↓
              COLLECT
                  ↓
               CONNECT
                  ↓
               VERIFY
                  ↓
               REPORT

And keep asking:

“What evidence supports this?”

That's a much better habit than simply collecting interesting information.

🧠 Quick OSINT cheat sheet

Concept What it means
OSINT Intelligence derived from publicly available information

Username investigation Looking for the same username across public platforms
Image OSINT Investigating an image's source and appearances
WHOIS A system/service category for accessing domain registration data
Verification Checking whether a finding is actually reliable
Evidence Information that supports a conclusion
Lead Something worth investigating further

🎯 One last thing

You don't need to become an OSINT expert overnight.

Start with something simple.

Take a fictional username.

Search it.

See where it appears.

Compare the profiles.

Look for connections.

Then ask yourself:

“What do I actually know, and what am I only assuming?”

That last question will save you from a lot of bad conclusions.

And honestly, that's one of the most important habits you can build in OSINT.

Don't just find information. Understand what it means.
