What Is DNS?

You remember names. Computers work with addresses. So who translates one into the other?

Think about how you use the Internet every day.

You probably don't type a string of numbers whenever you want to visit a website.

You type a name.

Maybe you enter a familiar domain into your browser, press Enter, and wait for the page to appear.

But we've already discovered something important.

Computers need IP addresses to communicate.

So if you type:

example.com

how does your computer discover the IP address it needs?

The mystery

Who translates a name that humans understand into an address that computers can use?

Imagine your phone contacts

Think about your phone.

You probably don't remember everyone's phone number.

Instead, you save:

“Mom”

When you want to call her, you tap her name.

Your phone looks up the number associated with that contact and uses it to make the call.

DNS works with a similar basic idea.

You give the system a human-friendly name.

DNS helps find the corresponding network information.

DNS is the Internet's naming system

DNS stands for Domain Name System.

Its job is to help translate domain names into IP addresses and provide other information about domains.

example.com
→
DNS
→
93.184.216.34
A simplified view of a DNS lookup

That's the basic idea.

But the real system is much more interesting than one giant directory containing every website on the Internet.

There isn't one giant DNS server

Imagine if one computer somewhere had to remember every domain name and every IP address on Earth.

Every device would have to ask that one computer for every lookup.

That wouldn't be a very practical design.

Instead, DNS is a distributed system.

Different DNS servers have different roles, and information can be cached along the way.

You don't need to memorize all of those server types yet.

For now, remember the important idea:

DNS is a distributed naming system, not one computer that knows everything.

Let's follow the lookup

You type a domain name into your browser.

Before the browser can communicate with the destination server, the system needs to find the appropriate IP address.

A simplified version of the journey looks like this:

Your device
→
DNS resolver
→
DNS system
→
IP address

Often, the resolver can answer immediately because it already has the information stored in its cache.

If it doesn't, it can perform the necessary DNS queries to find the answer.

Once the result is available, your device can continue the journey toward the destination.

And sometimes the answer is already nearby

This is where caching becomes useful.

If a DNS result was recently requested, it may already be stored temporarily by your device, operating system, browser, or DNS resolver.

There's no reason to perform the entire lookup again if a valid cached answer is available.

That's one reason DNS can feel almost invisible when you use the Internet.

A lot can happen without you seeing any of it.

Here's where security enters the story

DNS looks simple from the outside.

Ask for a name. Get an address. Continue the connection.

But what happens if the answer is wrong?

Think about it

What if someone could manipulate the answer your computer receives from DNS?

Instead of being directed toward the intended destination, a user could potentially be redirected somewhere else.

That's why DNS is an important part of security investigations.

Analysts may examine DNS queries to understand which domains a system attempted to contact.

They may look for unusual domain names, unexpected destinations, suspicious patterns, or connections that don't fit the normal behaviour of a system.

DNS can become a clue.

A domain name can tell you something

Imagine a company computer suddenly starts making repeated DNS queries for a strange domain that nobody in the organisation recognises.

That doesn't automatically prove anything malicious happened.

It could be a legitimate application, an update service, a misconfigured system, or something that simply hasn't been documented properly.

But it gives an analyst somewhere to look.

The question isn't “Is this domain bad?”

The better question is “Why is this system communicating with this domain?”

Context matters.

DNS isn't only about websites

Another useful thing to understand is that DNS isn't limited to turning website names into IPv4 addresses.

DNS can store different kinds of records that provide different pieces of information.

For example, DNS can be used for things related to:

A IPv4 address
AAAA IPv6 address
MX Mail servers
TXT Text-based information

You don't need to memorize these yet.

Just remember that DNS is more than a simple name → IP converter.

Now look at the journey again

At the beginning, all you did was type a website name.

But underneath that simple action, several pieces started working together.

Domain
→
DNS
→
IP
→
Port
→
Service

First, the human-friendly name has to be resolved.

Then the destination has to be reached.

Then the appropriate service has to receive the traffic.

And now we're getting close to the part of the journey where browsers and web servers actually start speaking to each other.

Remember this

DNS helps humans use names while networks use addresses. It quietly connects the two.
